## 一、这一期做了什么

前两期给了系统「记忆」和「记分牌」。这一期给它装上**裁判**，并明确一条边界：

> **Agent 只能提议，只有闸门能放行。**

四个模块：

| 文件 | 作用 | 能改什么状态 |
|---|---|---|
| `gate.py` | G1–G5 五条闸门 + `promote()` | hypothesis → testing（**唯一入口**） |
| `decay.py` | 连续 N 次低于阈值机械降级 | active → decaying（**唯一入口**） |
| `evolve.py` | 单维候选枚举 + BH-FDR + 提议 | 只能写 hypothesis |
| `audit.py` | 报告签发前 A1–A7 | 不写状态，只拦签发 |

配套给 `rules.py` 加了 `revise()`：**不改状态**地追加新版本（衰减计数、证据补录）。
它与 `transition()` 的分工是硬性的 —— 前者不碰状态，后者是状态机。

## 二、闸门 G1–G5

| 闸门 | 判据 | 来自哪次翻车 |
|---|---|---|
| G1 样本量 | n ≥ 30；n < 100 标「样本偏少」 | 避坑手册 §4.4：18 个样本做不了统计 |
| G2 扣费后超额 | 扣费后 > 0 **且** 相对基准 ≥ **0.215pp** | SKILL §9.3：基准 −0.113%/笔 + 成本 0.102% |
| G3 方向同向 | 分年（≥3 年）同号 | §9.4.2：只在一年为正 = 行情特征 |
| G4 剔除最大窗口 | 剔除后仍为正 | §9.7.2：复合档 41% 样本来自单月，剔除后转负 |
| G5 多重比较 | BH-FDR p < 0.05 | `robustness.py`：试 50 个挑最好 = 抽卡 |

**缺哪一项证据，G 就判不通过**，并写明「未提供」。
默认值不是中性选项，它是隐形的放行（SKILL §9.7.3）。

### 2.1 自己抓到的闸门漏洞（本轮最重要的发现）

第一版 G2 只要求「扣费后 > 0 且相对基准 > 0」。自检 U6 立刻打脸：

```
[FAIL] U6 · 演化器
   ✗ 植入的低位边缘被识别为通过：['EVO-LBC-Q1', 'EVO-ZONE-POS-120-Q1', 'EVO-ZONE-POS-120-Q2']
```

`EVO-LBC-Q1`（**连板数**分桶）通过了 —— 而连板数在测试数据里与收益**完全独立**。
它的证据是：

| 条件 | n | 均值 | 相对基准 | BH p | 结果 |
|---|---|---|---|---|---|
| ZONE-POS-120-Q1 | 151 | **+1.158%** | +1.031pp | <1e-6 | 真信号 |
| ZONE-POS-120-Q2 | 151 | +0.272% | +0.145pp | 0.030 | 边缘残余 |
| **LBC-Q1** | 492 | +0.160% | **+0.034pp** | 0.016 | **假信号** |

问题就在 **+0.034pp**：统计上 t=2.78、BH p=0.016 都「显著」，
但 0.034pp 连成本假设的零头都不够。plan 里写的是「必须跨过 **0.215%** 毛超额门槛」，
我漏实现了量级要求。

修复：加 `MIN_EFFECT_PP = 0.215`，G2 要求 `相对基准 ≥ 0.215pp`。
修复后：

```
✓ 植入的低位边缘被识别为通过：['EVO-ZONE-POS-120-Q1']
✓ 与收益无关的连板数维度不得通过（实际通过：[]）
✓ 纯噪声下通过的条件数 0 ≤ 1
```

并且把这条写成**回归测试**（U6 里那条 `LBC` 断言就是为这个 bug 留的）。

> 这条值得单独记：**统计显著 ≠ 经济显著**。t 值只回答「这个差是不是噪声」，
> 不回答「这个差够不够付手续费」。闸门必须两者都问。

## 三、衰减监控（机械降级）

```
连续 3 次滚动均值 < 阈值 → active 降级为 decaying
达标一次 → 计数清零
取不到表现数据 → 计数**保持不变**（不许静默清零掩盖失效）
复活 decaying → active 必须 human/gate，且必须写理由
```

为什么必须机械：人的失效发现机制是「亏到受不了」，那时已经晚了；
而规则失效的第一信号是「统计上不再为正」，它在亏损变成痛之前就出现。

`SKILL §9.3` 的实测结论支持这个设计：低位档正期望逐年衰减
（2024 +0.982% → 2026 +0.189%），「这周好使」不能当常态。

## 四、报告审计 A1–A7

| # | 检查 | 防的是 |
|---|---|---|
| A1 | 买入结论必须附可买性 / 被排除项 / 空仓出口 | 给一只封死涨停的票却不校验明天能否成交 |
| A2 | 每个数字都要标来源 | LLM 编数字、记忆里的旧数字混入 |
| A3 | 文本参数 == 机器参数 | §9.7.3：文本说 Z1 适用、引擎 Z1 关闭 |
| A4 | 同步指标不许写成预测句式 | 华泰金工：量价类情绪指标无领先性 |
| A5 | 扣费后为负必须标注 | 把负期望包装成「优于基率」 |
| A6 | n<30 必须标注样本极少 | 18 个样本做不了统计 |
| A7 | 已知偏差必须声明 | 假装没有回放/实操之间的偏差 |

任意 `blocker` 不通过 → `assert_signable()` 抛错，**拒绝签发**。

### 4.1 A4 的双向对照

正则最容易变成「永远不报」或「永远报」，所以 U4 对 A4 做了双向断言：

**必须被拦**（同步指标写成预测）：

- 「情绪冰点，明日必然反转」
- 「冰点之后必然反弹」
- 「涨停家数预示明天走强」

**必须放过**（合规写法，不含预测句式）：

- 「当前情绪读数为同步指标，据此降低仓位至 20%」
- 「涨停家数 69 家、炸板率 16.9%，仅用于仓位档位，不构成方向判断」
- 「连板高度压缩至 2-3 板，说明赔率下降，故降低使用强度」

负例是关键：如果它们也被拦，说明规则写死了、没法正常写报告。

## 五、演化器

### 5.1 三条硬约束

1. **只做单维度**。`MAX_LEAVES_PER_RULE = 1`，`build_conditions()` 里硬校验。
   理由：§9.7.2 已证明「低位×回调」复合档是 2024-02 单月的产物，剔除后转负。
2. **不自己算收益**。输入 `rows` 里的 `ret_pct` 必须是已扣费净收益，
   口径由 `backtest_core` 统一计算 —— 口径分叉本身就是静默错误的来源。
3. **拒绝要记住**。`rejected_keys()` 里的 rule_id 不再重复提议，
   否则「试 50 个条件挑最好的」会无限循环。U6 验证了第二轮 `tested == 0`。

### 5.2 BH-FDR

手算可验证（U5）：

```
[0.01, 0.02, 0.03, 0.04]        → 全部校正为 0.04
[0.01, 0.5]                     → [0.02, 0.5]
[0.001]                         → [0.001]（单个不放大）
```

并断言「校正后 p 不小于原始 p」（BH 的基本性质）。

### 5.3 植入边缘测试

U6 造了 600 行、跨 2023–2026 四年的数据，只有 `zone_pos_120 < 0.3` 有正期望：

- 真边缘被抓到（`EVO-ZONE-POS-120-Q1`，t=14.8）
- 无关维度（前5日涨幅、连板数）全部不通过
- 纯噪声数据下通过数 = 0

> 这里也暴露过一次测试数据缺陷：第一版只造了 2026 一年的日期，
> 导致 G3「分年同向 ≥3 年」必然失败，连真边缘都过不了。
> 那不是闸门太严，是测试数据不满足前提 —— 修数据，不是放松闸门。

## 六、一个诚实的结果：种子规则全部过不了闸门

把 `data/virtual/rules.jsonl` 里从原包导入的三条规则喂给闸门：

| 规则 | 结果 | 原因 |
|---|---|---|
| `POS-120-LOW` | ❌ 不通过 | G5：原文没给 BH-FDR p 值 |
| `CHG5D-NEG` | ❌ 不通过 | G5：同上 |
| `SEAL-RATIO-BUYABLE` | ❌ 不通过 | G1–G5 全缺：它是机制性判据，不是统计结论 |

外加两条 ⚠ 提示：

```
thin_margin:净超额仅 +0.050%/笔，小于单次往返成本假设 0.1%；成本若高出 0.050pp 即转负
no_median_reported:只给了均值，无法判断是否「均值正、中位负」
```

**这不是闸门有问题，这是闸门在正确工作。** 原包没做多重比较校正，
所以它的证据不足以让规则在我们的系统里活化。三条规则保持 `hypothesis`。

要让它们活化，只有一条路：**用我们自己的数据重跑并算出 BH-FDR**。
这正是 P3 之后该做的事，也是 `evolve.py` 存在的意义。

> 顺带修正过一处措辞：第一版提示写的是「扣费后仅 +0.050%，不到单次往返成本」——
> 但 `after_cost_pct` 本来就是**扣费后**的数，说它「不够付成本」是自相矛盾的。
> 已改成「净超额小于成本假设的 1/2，成本高出 0.05pp 即转负」。

## 八、怎么用

```bash
# 1) 跑一轮演化（需要 rows：特征 + 已扣费净收益）
python -c "
from portal.virtual import evolve
rows = [...]   # 由 tagging + backtest_core 组装
res = evolve.run(rows)
print('通过', [e['rule_id'] for e in res['passed']])
print('拒绝', [e['rule_id'] for e in res['rejected']])
print(evolve.propose(res))
"

# 2) 把某条 hypothesis 送闸门
python -c "
from portal.virtual import gate
print(gate.promote('EVO-ZONE-POS-120-Q1', {...}, actor='gate'))
"

# 3) 衰减巡检
python -c "
from portal.virtual import decay
print(decay.sweep({'EVO-ZONE-POS-120-Q1': -0.2}))
print(decay.health())
"

# 4) 报告签发前自检
python -c "
from portal.virtual import audit
audit.assert_signable(report_payload)   # 不通过就抛错
"
```
