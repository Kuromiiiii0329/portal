## 一、这一期做了什么

把「盘前写计划 → 次日机械回放 → 滚动账本 → 用账本迭代规则」这条闭环接通。
核心只有一句话：

> **成交由算法判定，不许人工叙述。**

新增三个模块：

| 文件 | 作用 |
|---|---|
| `virtual/plan.py` | 计划构造 / schema 校验 / `params_hash` / 冻结 + 锚定 |
| `virtual/fill_model.py` | 费用模型 / 股数取整 / R0–R4 竞价判定 / 排队撮合 |
| `virtual/settle.py` | 买入日与平仓日结算 / 三把尺子 / 账本追加 |

## 二、关键机制

### 2.1 三把零自由度尺子

**缺一个，整套系统就失去意义**（SKILL §7.2.1）。

| 尺子 | 成分 | 回答什么问题 |
|---|---|---|
| 大盘 | 沪深300 当日涨跌 | 有没有跑赢「什么都不做」 |
| 基准组合 | T 日**全部**涨停股，次日开盘等权 | 选股有超越「无脑买昨日涨停」吗 |
| 影子组合 | **自己选的三只**，不做 gate、不做 R 过滤 | 执行规则是加分还是减分 |

口径**统一到投入资金**：

```
执行贡献 = 实际 − 影子
选股贡献 = 影子 − 基准
```

> 为什么不能用总资产当分母：分母不同就没法比。原包第一版就是这么错的
> （SKILL §7.2.1 明确写了「分母不同没法比」）。

实测价值（原包 2026-09-28 冒烟数据）：实际 +6.071%（仓位仅 29.7%）／影子 +8.054%／
基准 +8.230% → 执行 **−1.983pp**、选股 **−0.176pp**，两项都是减分。
**没有对照组，这个结论永远发现不了**，人会一直以为「规则帮我避开了风险」。

### 2.2 排队撮合而不是拍概率

打板最大的自欺是「假设涨停价一定能买到」。所以成交必须建模：

```
挂单时记录排队位置 queue_pos（= 当时买一量）与 vol_at_place（= 当时累计成交量）
成交条件 = (当前累计成交量 − vol_at_place) >= queue_pos
```

- 一字板封死 → 后面没有新成交量 → **永远轮不到你**（物理正确）
- 炸板放量 → 新成交量迅速超过排队量 → **自然成交**（物理正确）

这个模型不需要「假设成交概率」，只需要两个可观测量。自检 T6 用三条 tape 验证：
一字板不成交、放量成交、新增量恰好等于排队量时成交（用 `>=`）。

### 2.3 R0–R4 竞价判定

| 规则 | 条件 | 结果 |
|---|---|---|
| R0 | 委托额 ÷ 竞价成交额 > 5% | 不成交（盘子太薄，排不上） |
| R1 | 竞价涨幅 ∈ (0%, +7%] | **成交**，价 = 竞价开盘价 |
| R2 | 竞价涨幅 ≤ 0% | 不成交（承接失败） |
| R3 | 竞价涨幅 ≥ +9.5% | 不成交（排在封单后面） |
| R4 | 竞价涨幅 > +7% | 不成交（不追高） |

判定顺序 R0 → R2 → R3 → R4 → R1。自检 T5 覆盖全部边界：0% / 7.0% / 7.01% / 9.49% / 9.5%。

### 2.4 结算前两道护栏

1. **锚点校验**：`anchor.verify()` 不通过 → 抛 `SettleAbort`，**不写账本**。
   自检 T10 用「改一个空格」验证。
2. **日期护栏**：分时日期 ≠ 交易日 → 抛 `SettleAbort`。
   理由（SKILL §7.4）：行情还没生成时跑一次会拿前一天数据污染账本，**而且不报错**。

### 2.5 平仓三层 + Z1

| 层 | 条件 | 处理 |
|---|---|---|
| 止损层 | 默认**关闭** | 41,655 笔回测证明机械止损是负期望（SKILL §9.7） |
| 收盘平仓 | 正常情形 | 以收盘价卖出，**与回测口径统一** |
| Z1 顺延 | 平仓日收盘涨停 | 不卖，顺延一次 |
| L3 卖不出 | 收盘跌停封死 | 记 `forced_hold`，**不许假装卖掉了** |

自检 T9 三个分支全覆盖，并且做了**开关对照**：同一天、同一数据，
`z1=True` 必须顺延、`z1=False` 必须平仓 —— 证明开关真的在起作用。

### 2.6 计划 schema 的硬校验

`plan.validate()` 会直接拒绝这些（对应原包真实事故）：

| 拒绝条件 | 为什么 |
|---|---|
| `picks` 超过 3 只 | 机制约束 |
| 止盈档 > 涨停价 | 超过涨停价的止盈单当天根本不可能成交，等于没写（SKILL 铁律 3） |
| 止损位 ≥ 昨收 | 买入即触发止损，规则自相矛盾 |
| `limit_up` 与「昨收 × 板块幅度」不符 | 涨停价算错，后面所有档位全失效 |
| `exit_rule` 缺 `price_basis` / `use_stop` / `z1` | **默认值不是中性选项，它是隐形的规则**（SKILL §9.7.3） |
| `open_gate.conditions` 为空 | 必须显式写空仓出口 |
| 人工项未声明 `default` | 静默默认通过 = 没有过滤（MEMORY.md 追加纪律） |

## 三、过程中改掉的两个真问题

### 3.1 平仓规则永远静默不触发（代码 bug）

`settle_exit()` 要从持仓里读 `limit_up` / `limit_down` 才能判 Z1 与 `forced_hold`，
但 `settle_buy()` 写 fills 时**根本没写这两个字段** —— 于是：

- Z1「收盘涨停顺延」永远不会触发；
- L3「跌停封死 forced_hold」永远不会触发；
- 而且**不报错**，只是默默按普通平仓处理。

这是写 T9 时才发现的：我给 `_pick()` 造了 `limit_up`，但断言 `pos0["limit_up"]` 存在时直接失败。
修复：`settle_buy()` 落盘持仓时一并带上 `limit_up / limit_down / stop / tp1 / tp2`，
并在代码注释里写明「少了这两个字段，那两条规则永远不会触发 —— 而且是**静默**不触发」。

### 3.2 自检没有隔离（测试 bug）

S3（锚点）会故意把 `anchors.json` 改坏来验证断链检测，但**没有还原**。
于是同一进程里后跑的 T8/T9 全部因为「锚点链已损坏」而失败：

```
[FAIL] ERR · check_settle_buy 执行异常
   ✗ SettleAbort: 锚点校验未通过 … 记录内容被改（chain_sha256 不匹配）
```

这其实说明被测代码是对的（它确实拒绝了被污染的链），是**测试没隔离干净**。
修复：S3 开头保存 `anchors.json`、结尾还原，并加一条断言「还原后链完整」。

> 教训值得记：**一个会污染全局状态的测试，比没有测试更危险** ——
> 它会让后面的失败看起来像是被测代码的问题。

## 五、怎么用

```bash
# 盘前：写计划 → 冻结并锚定（锚定后再改，结算会中止）
python -m portal.virtual.plan list
python -m portal.virtual.anchor verify 20261008

# 次日买入日结算（--dry 只打印判定过程，不写账本）
python -m portal.virtual.settle 20261008 --dry
python -m portal.virtual.settle 20261008

# 平仓日结算
python -m portal.virtual.settle 20261008 --exit
```

`settle` 的 CLI 输出会逐条打印 gate 明细、每笔成交/拒绝的规则与理由、三把尺子与归因。
