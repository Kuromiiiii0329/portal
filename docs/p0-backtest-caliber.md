## 一、修的是什么

`portal/backtester.py` 原来自己算收益，有 6 处**不报错、只出错数**的口径缺陷，
另加 2 处本仓库特有的数据陷阱。全部来自《回测避坑手册》与《净值口径说明》的实测案例。

| # | 缺陷 | 后果 | 依据 |
|---|---|---|---|
| 1 | 收益用 `close[T+d]/close[T]` | 把「信号日收盘 → 次日开盘」的隔夜跳空算进去，而实盘 T+1 开盘才买得到 | 手册 §3.1（同类错误曾算出 +21,248%） |
| 2 | `d=1` 等于当日买当日卖 | 违反 A 股 T+1，物理上不可能 | 手册 §3.2 |
| 3 | 完全不扣成本 | 每笔恒定虚高 0.10pp | 手册 §3.3（错法实测差 24% 净值） |
| 4 | 无基准、无超额 | 牛市里「赚 20%」可能是跑输 | 手册 §4.2 |
| 5 | 只有均值与胜率 | 正中「均值正、中位负」的骗局 | 手册 §4.1 |
| 6 | 无分年稳定性 | 只在一年成立的是行情特征，不是规律 | 手册 §4.5 |
| 7 | 依赖 `pct_chg` 字段 | 该字段在缓存增量批次边界被**静默写成 0**（实测 11 行/3695 行） | 本仓库实测 |
| 8 | 不剔除「次日开盘即涨停」 | 一字板物理上买不进，留在回测里系统性高估 | 打板工具包实测：一字板次日 +6.93% 但买不到 |

## 二、改成了什么

```
入场 = T+1 开盘价（信号日收盘确认）
出场 = T+1+h 日收盘价（h = 持有交易日数，满足 T+1）
成本 = 往返 0.10%，只在买入/卖出两个时点各扣一次
基准 = 同一只票、同一持有期、同口径的无条件收益（零自由度）
回报 = 均值 / 中位数 / 胜率 / t 值 / 分年 / 超额
剔除 = 次日开盘涨停 + 复权断裂，并报告剔除数
```

新增文件：

| 文件 | 作用 |
|---|---|
| `portal/backtest_core.py` | 内核。所有收益公式**只此一处**，审计/结算/报告都复用它 |
| `portal/backtest_audit.py` | 11 条对照实验自检 + 数据体检 CLI |
| `portal/backtester.py` | 改为薄封装，对外契约不变 |

## 三、自检的 11 条（这是本次交付的核心）

`python portal/backtest_audit.py --real`

| ID | 检查 | 为什么必须有 |
|---|---|---|
| C1 | 算术已知答案 | 手算可验证的确定性序列，证明收益公式本身对 |
| C2 | T+1 入场口径 | 同时断言「等于新口径」**且**「不等于旧口径」——证明修正真的生效 |
| C3 | 成本只扣一次 | 断言扣费额 == 单次往返，**且** ≠ 按日扣 |
| C4 | 负向控制：全部涨停开盘 | 必须全部剔除；配对正向对照证明不是把所有样本都杀掉 |
| C5 | `pct_chg` 免疫 | 打乱该字段后统计必须完全一致 |
| C6 | 探针有效性 | 塞入已知错误值，断言必须**能失败**——否则「通过」不代表什么 |
| C7 | 向后兼容 | 旧字段名/类型全保留，`http_handler`/`tasks`/`prompts` 不改也能跑 |
| C8 | 真实数据独立复算 | 第二套独立实现逐笔比对：相关系数 1.000000、平均偏差 0.00e+00 |
| C9 | 真实缓存体检 | 必须真的抓到 `pct_chg` 静默归零，否则说明探针坏了 |
| C10 | 行序不变性 | 打乱 CSV 行序后体检指标一致 |
| C11 | 首行回卷防护 | 见 §五 |

## 四、实测影响（诚实版）

同一批数据（6 只票 × 9 信号 × 3 日持有 = 50 个条目）：

| 指标 | 数值 |
|---|---|
| 新旧均值差（旧 − 新） | 平均 **−0.23pp**，最大 **+1.72pp** |
| **新旧均值符号翻转** | **10 / 50 条** ← 旧版把亏损信号报成了盈利，反之亦然 |
| 「均值正、中位负」 | **9 / 50 条** ← 旧报告里完全看不到 |
| 旧胜率与新胜率之差 | 平均 −4.39pp |

### 必须说清的一点

**旧口径的误差不是"恒定高估"，而是"方向不定的噪声"——这比恒定偏差更危险。**

拆开看：
- 成本那一项**恒定**让旧版虚高 0.10pp，这个是可预期的；
- T+1 入场那一项等于「信号日收盘 → 次日开盘」的平均跳空，**可正可负**。
  本样本里平均约 −0.13pp（高开日多时则为正，见 C2 的构造：每天高开 2% 时旧口径虚高 +1.99pp）。
- 两项相加得到 −0.23pp，但均值掩盖了真实伤害：**10/50 条结论的符号被改变**。

恒定偏差你可以心里打折；**符号翻转不行**——你无法事后知道自己当时看的是哪一边。

## 五、过程中抓到的两个真 bug（记录在案）

### 5.1 `np.roll` 首行回卷

`np.roll(close, 1)` 会把**最后一行卷到第一行**，于是首行与「全序列最后一天的收盘价」相比。
在 002466 这种从 112 元跌到 40 元的票上，首行会被算出 −64% 的假涨跌，直接误判成复权断裂。

表现：同一份数据，我的独立探针报 2 行 `pct_chg` 静默归零，而 `data_quality()` 报 3 行。
差的那一行就是首行。**两个自己写的数字对不上，就说明其中一个在骗人。**
修复：`_daily_moves()` 显式把首行置 0，并加了 C11 专门守这个回归。

### 5.2 体检结果依赖 CSV 行序

`data_quality()` 原先直接用传入的行序算相邻涨跌。行序一变，结果就变。
修复：内部强制按日期排序，并加 C10 守。

## 六、兼容性

- `run_backtest(df, forward_days, code=None)` 签名向后兼容，**新增可选参数 `code`**。
  传了 `code` 才能按板块推断涨跌停幅度，从而正确剔除 20cm 票的「开盘涨停」样本。
  已同步修改两个调用方：`srv/http_handler.py`、`srv/tasks.py`。
- 返回结构只增不改：旧的 `signals / total_days / stock_days / stats{win_rate,avg_return,valid}`
  全部保留且类型不变。
- **缓存作废**：新增 `caliber_version`（当前 = 2）。`data_cache` 里的旧回测结果会被
  `is_current_caliber()` 判定为过期并重算，否则「修好口径但读旧缓存」等于没修。
- `srv/prompts.py` 现在会同时给 LLM **中位数与超额**，并附口径声明——
  只喂「胜率X%/均收益Y%」，模型会把这些数字当成可靠结论复述。
